# 篮球课堂算法系统 — `action_type` / `phase` 对齐词表

> **用途**：供后端对接算法输出时，统一 `action_type` 与 `phase` 的 canonical 字符串、字段映射及已知不一致项。  
> **规范来源**：[`src/action/registry.py`](../src/action/registry.py)、[`src/output/schema.py`](../src/output/schema.py)、[`configs/actions/*.yaml`](../configs/actions/)、GT 文档 [`docs/v3测试集动作真值.md`](v3测试集动作真值.md)  
> **示例输出**：`data/outputs/v3/`（v3 批处理产物）

---

## 1. `action_type` 词表

| value | 中文 | 定义 / 适用场景 | 来源模块 |
|-------|------|-----------------|----------|
| `free_throw` | 罚篮 | 站定出手、无明显纵跳；投篮族，需 cam_04 球过筐门控 + 可判进球 | **action**：`multicam_release.py` 检测 release → `detect.py::classify_release_action`；**pipeline** 会话级重标（如纯跳投课 suppress） |
| `jump_shot` | 跳投 | 与罚篮形态相近但明显起跳（双脚离地 + pelvis/ankle 上升） | 同上；**pipeline** 可能将 `free_throw` 重标为 `jump_shot`（`airborne_pose_to_jump_shot` 等） |
| `layup` | 上篮 / 三步上篮 | 助跑近筐、人→筐距离缩短 + 高位移 | 同上（`near_rim_finish`、`drive_toward_hoop` 等 reason） |
| `triple_threat` | 三威胁 / 突破 | 蹲姿/重心下降/变向启动；**含突破，无独立 `dribble` 标签** | **action**：`pose_only.py::classify_pose_only_window`（pose 为主，球为辅） |
| `pass` | 传球 | 双手胸前 + 球飞过/离手；需 ≥2 人 + 参与者归因 | **action**：`pose_only.py`；`participant_ids` 为 `[passer, receiver]` |
| `unknown` | 未知 | 分类置信度不足或未识别窗口 | **registry** 兜底；**export** 无 clip 上下文时的默认值 |

### 缩写（GT / 评测脚本）

| 缩写 | 规范值 |
|------|--------|
| `ft` | `free_throw` |
| `js` | `jump_shot` |
| `layup` | `layup` |
| `tt` | `triple_threat` |
| `pass` | `pass` |

### 别名 / 遗留值（入库前会被归一化）

定义于 `src/action/registry.py::normalize_action_type()`：

| 输入 | 归一化为 | 说明 |
|------|----------|------|
| `dribble`, `drive`, `breakthrough` | `triple_threat` | 无独立运球/突破标签 |
| `shot`, `jumper` | `jump_shot` | 旧称 |
| 其它任意字符串 | `unknown` | 兜底 |

### v3 输出示例

| 文件 | 示例 |
|------|------|
| `group_05/report.json` | `"action_type": "free_throw"` ×17 |
| `group_06/report.json` | `"action_type": "layup"` ×6 |
| `group_07/report.json` | `"action_type": "jump_shot"` ×11 |
| `group_03/report.json` | `"triple_threat"` + `"jump_shot"` 混合 |
| `group_06/summary.json` | `"action_type_hist": {"layup": 6}` |

> v3 测试集**无传球组**；`pass` 示例见 v2：`data/outputs/v2/group_06/report.json`。

### 动作族划分（影响下游逻辑）

定义于 `src/action/registry.py`：

| 族 | 成员 | 特征 |
|----|------|------|
| 投篮族 | `free_throw`, `jump_shot`, `layup` | 需 cam_04 rim 门控；有 `release_ms`；可关联 make/miss |
| Pose-only 族 | `triple_threat`, `pass` | 不依赖 cam_04 做分类；通常 `release_ms: null` |

## 2. `phase` 词表（clip vs record vs scoring）

系统存在 **三层 phase 命名空间**，后端对接时需区分：

1. **Clip 阶段**（`clips[].phases[].name`）— action 切分产出，最完整
2. **Record 阶段**（`records[].action_phase`）— export 写入，**子集受限**
3. **评分模板阶段**（`configs/actions/*.yaml`）— 教学指标用，与 runtime 可能不完全一致

### 2.1 规范 Record 枚举（Pydantic）

定义于 [`src/output/schema.py`](../src/output/schema.py)：

`load` · `set` · `release` · `follow_through` · `full` · `none`

| value | 中文 | 定义 | 来源模块 |
|-------|------|------|----------|
| `load` | 蓄力 | 出手前前半段 / pose-only 窗口前半 | **action** 切分；**export** 标注到 record |
| `set` | 设定点 | 蓄力后、release 前（罚篮形态） | **action**（`free_throw` 及被重标但未改 phase 的 `jump_shot`） |
| `release` | 出手 | 手腕 release 峰附近（±2 帧） | **action**；dashboard 取角主锚点 |
| `follow_through` | 跟随 | release 后跟随动作 | **action** |
| `full` | 全片段 | 在 clip 内但未命中任何子 phase 边界 | **export** `_phase_at_ms` 兜底 |
| `none` | 无 | 不在任何 clip 内，或非 schema phase 被截断 | **export** 默认 / 截断值 |

### 2.2 Clip 阶段（按 `action_type`）

#### 投篮族 — 由 `multicam_release.py::_phases_for_action` 生成

| action_type | phase 序列 | 中文（来自 yaml `display_name`） |
|-------------|------------|----------------------------------|
| `free_throw` | `load` → `set` → `release` → `follow_through` | 蓄力 → 设定点 → 出手 → 跟随 |
| `jump_shot` | `load` → **`takeoff`** → `release` → `follow_through` | 蓄力 → **起跳** → 出手 → 跟随 |
| `layup` | `approach` → `gather` → `takeoff` → `release` → `finish` | 起步 → 收球 → 起跳 → 出手 → 终结 |

**v3 示例：**

- `group_05`（罚篮）：phases = `load/set/release/follow_through`；`motion.json` 中 `action_phase: "release"` @ `3449ms`
- `group_07`（跳投）：phases 含 `takeoff`（无 `set`）
- `group_06`（上篮）：phases = `approach/gather/takeoff/release/finish`

#### Pose-only — 由 `pose_only.py` 生成

| action_type | phase 序列 | 中文（语义） |
|-------------|------------|--------------|
| `pass` | `load` → `action` → `recover` | 准备 → 传球动作 → 恢复 |
| `triple_threat` | `load` → `action` → `recover` | 准备 → 三威胁/突破 → 恢复 |

**v3 示例：** `group_03/report.json` 中 `triple_threat` clip phases = `load/action/recover`  
**v2 示例：** `group_06/report.json` 中 `pass` clip，`participant_ids: ["stu_02","stu_03"]`

#### 评分模板专用 phase（**不一定出现在 clip 输出**）

来自 [`configs/actions/triple_threat.yaml`](../configs/actions/triple_threat.yaml)：

| value | 中文 | 用途 |
|-------|------|------|
| `stance` | 威胁站姿 | 评分模板 |
| `jab_step` | 刺探步 | 评分模板 |
| `drive_trigger` | 突破启动 | 评分模板 |

> `pass` **无** scoring yaml；`scoring/fusion.py` 按模板 phase 名去 clip.phases 里查找，找不到则跳过该指标。

### 2.3 易混淆：Sync Event `kind`

`src/cameras/event_sync.py` 中 `SyncEvent.kind = "release"` 表示**多机位时间对齐事件**，不是 motion phase，后端勿混用。

## 3. JSON 字段映射

### 3.1 文件级对照

| 文件 | 路径示例 | 携带字段 |
|------|----------|----------|
| **motion.json** | `data/outputs/v3/group_XX/motion.json` | 顶层 `clips[]` + `records[]` |
| **report.json** | 同目录 | 仅 `clips[]`（与 motion.clips 同源） |
| **dashboard.json** | 同目录 | `shots[]`（由 report + outcome 构建） |
| **summary.json** | 同目录 | 会话级汇总，无 phase 明细 |
| **session 原始** | `data/sessions/{id}/actions/{student_id}.json` | `ActionClip` 全量（含 `metadata.action_classify`） |

### 3.2 字段明细

```
motion.json / report.json — clip 级
├── clips[].action_type          # 规范 action 标签
├── clips[].clip_id              # "{student_id}:{index}"
├── clips[].start_ms / end_ms
├── clips[].release_ms           # 投篮族有值；pass/TT 通常为 null
├── clips[].anchor_camera        # 默认 cam_03
├── clips[].zone_id              # 区域标签（v3 多为 null；示例 schema 有 "free_throw"）
├── clips[].participant_ids      # pass: [传球者, 接球者]；其它: [shooter]
└── clips[].phases[]
    ├── name                     # ★ phase 规范字符串（完整集合见 Section 2.2）
    ├── start_ms / end_ms
    └── start / end              # 锚机位帧号

motion.json — record 级
├── records[].action_type
├── records[].action_phase       # ★ 仅 schema 六值；见 Section 4 截断问题
├── records[].clip_id
├── records[].timestamp_ms
├── records[].skeleton_3d
└── records[].ball

dashboard.json — shot 级（UI/教师端）
├── shots[].action_type
├── shots[].phases               # string[]，phase 名列表（非对象）
├── shots[].phase_angles         # { phase_name: { left_knee, right_elbow, ... } }
├── shots[].release_angles       # release 时刻关节角
├── shots[].release_ms / time_ms # 投篮显示 release；pass/TT 用 start_ms
├── shots[].made / result        # MAKE | MISS | —
└── shots[].participant_ids

summary.json
├── action_type                  # 会话 dominant 类型
├── action_type_hist             # { "layup": 6, ... }
└── action_type_source           # 固定 "auto_classify"
```

### 3.3 Pipeline 阶段 → 字段写入关系

```
perception   → student_id, skeleton (pose2d)
sync/pose3d  → timestamp_ms, skeleton_3d, pose_source
action       → action_type, clips[].phases[], release_ms, clip_id
shot         → ball, outcomes (made/miss) → dashboard.result
export       → motion.json (records + clips)
scoring      → 读 clips.phases + angles → report.html（非 v3 主输出）
dashboard    → dashboard.json（shots 展平）
```

### 3.4 后端对接建议

1. **动作事件列表**：读 `report.json` 或 `motion.json` 的 `clips[]`
2. **帧级 phase**：优先 `clips[].phases[]`（完整）；`records[].action_phase` 仅作罚篮/跳投四段近似
3. **关节角**：读 `dashboard.json` 的 `phase_angles` / `release_angles`
4. **进球**：`dashboard.shots[].made` 或 session `shot_outcomes/outcomes.json`（按 `clip_id` 关联）

## 4. 不一致项 / TODO

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| 1 | **`schema.ActionPhase` 与 runtime clip phase 不同步** | `export.py` 仅允许 6 个 record phase；`takeoff/approach/gather/finish/action/recover` 在 record 层全部变成 `"none"` | 后端读 **clip.phases**，不要仅依赖 `records[].action_phase`；或扩展 schema + export 白名单 |
| 2 | **`jump_shot` phase 名不稳定** | 正常路径为 `takeoff`（`multicam_release`）；但从 `free_throw` 重标时 **不更新 phases**，残留 `set`（v3 `group_03` 9×`set` vs 3×`takeoff`） | 对接时：`jump_shot` 的第二段可能是 `set` 或 `takeoff`，语义均为「出手前准备/起跳」 |
| 3 | **文档 vs schema vs yaml 三套 phase** | `docs/输出格式设计.md` §3.3 列出 `approach/gather/takeoff/finish` 作 record 示例，但 schema 未收录 | 以 **clip 实际输出 + yaml** 为准；文档待修订 |
| 4 | **评分模板 vs runtime phase（triple_threat）** | yaml 用 `stance/jab_step/drive_trigger`；runtime 用 `load/action/recover` → 评分模块常 skip | 教学评分需 phase 映射表；事件检测直接用 runtime 名 |
| 5 | **`detect_shooting_phases` 遗留路径** | 非 layup 统一用 `load/set/release/follow_through`（无 `takeoff`） | 生产主路径是 `multicam_release`；单测/旧脚本可能仍走 detect |
| 6 | **`pass` 无 v3 批处理样例** | v3 测试集未覆盖传球 | 对齐测试用 v2 `group_06` 或补跑 v2 testset |
| 7 | **`zone_id` 多为 null** | schema 示例有 `zone_free_throw`，v3 输出普遍 null | 区域标签非当前 v3 必需字段 |
| 8 | **`action_type` 参数已废弃** | `segmenter.py` 传 `action_type=` 会 warn 并忽略 | 后端勿期望外部注入 action 类型 |

## 5. 快速参考：canonical 字符串一览

**action_type（6 个）：**  
`pass` · `triple_threat` · `free_throw` · `jump_shot` · `layup` · `unknown`

**phase — record 层（6 个）：**  
`load` · `set` · `release` · `follow_through` · `full` · `none`

**phase — clip 层扩展（按动作）：**

- 罚篮：`load`, `set`, `release`, `follow_through`
- 跳投：`load`, `takeoff`（或遗留 `set`）, `release`, `follow_through`
- 上篮：`approach`, `gather`, `takeoff`, `release`, `finish`
- 传球/三威胁：`load`, `action`, `recover`
- 评分专用（triple_threat yaml）：`stance`, `jab_step`, `drive_trigger`

如需后端 JSON Schema 文件，可直接以 [`src/output/schema.py`](../src/output/schema.py) 的 Pydantic 模型为准；clip phase 的完整枚举建议后端按 **action_type 分支** 校验，而非单一全局 enum。
