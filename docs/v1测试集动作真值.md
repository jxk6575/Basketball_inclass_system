## 总原则

- **每个 group 只出现下文列出的动作**，不存在未提及的动作类型。
- 验证时以「召回这些动作、且不要大量误检其它类型」为准。
- v1 **无独立注册切片**：身份由批处理在各组内自动注册（常见 ID 形如 `stu_g01` / `stu_g0X_p2`）；下文「人物」列多为 `—`（单人组）或未标注字母代号。

## 验证建议

1. **身份**：各组内自动注册即可；不强制与字母代号一一对应。双人场景可能出现 `stu_g0X` / `stu_g0X_p2`。
2. **group1–8**：以各组时间轴为准；输出目录 `data/outputs/v1/`。
3. **时间同步**：先对齐 `data/test_data_v1/sync/group_XX.json`，再跑批处理。
4. **group5**：确认工作集视频已是裁后版本，且输出为裁后重跑结果后再对照上表。
5. **类型约束**：例如 group1–3/6 不应大量出现 `layup`/`pass`；group8 以 `pass` 为主；group7 允许 `tt`+`layup`/`js` 组合。
