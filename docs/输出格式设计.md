# Session 输出格式设计

> 更新：2026-07-20  
> 状态：schema 以 `src/output/schema.py` 为准；v1 批处理的实际落盘路径见下  
> 示例：`data/schema_examples/session_output.example.json`（最小样例）

---

## 1. 设计目标

在单个 JSON（或 JSONL 流）中，为下游（3D 可视化、评分、教师端、进球判定）提供统一载荷：

| 必填概念 | 字段 | 说明 |
|----------|------|------|
| 学生 | `student_id` | 注册时的 **UUID** 或批处理短 id（如 `stu_g01`） |
| 时间 | `timestamp_ms` | **锚时钟**（默认 cam_03）毫秒；跨机位用 `alignment.json` 的 offset 换算 |
| 动作类别 | `action_type` | `pass` / `triple_threat` / `free_throw` / `layup` |
| 三维骨架 | `skeleton_3d` | 世界坐标系下关节点（伪 3D 时为 `pseudo3d`） |
| 篮球点位 | `ball` | 世界坐标 `[x,y,z]`，未检测时为 `null` |

## 2. 文件层级

### 2.1 实际路径（v1 批处理）

```
data/outputs/v1/group_XX/
  motion.json          # SessionOutput 风格导出
  report.html          # 评分报告（若有）
  viz/phases.mp4       # 可视化
```

正式 session 目录（编排器）：

```
data/sessions/{session_id}/
  perception/cam_XX/pose2d.json
  sync/alignment.json
  actions/{student_id}.json
  shot_outcomes/...
  export/              # 可选：统一 SessionOutput 导出
```

单视频 demo：

```
data/model_raw_data/outputs/{slug}/motion.json
```

### 2.2 顶层结构 `SessionOutput`

```json
{
  "session_id": "<uuid>",
  "generated_at": "2026-07-07T02:30:00Z",
  "coordinate_system": { ... },
  "clips": [ ... ],
  "records": [ ... ],
  "metadata": { ... }
}
```

| 字段 | 作用 |
|------|------|
| `coordinate_system` | 统一说明所有 3D 点的坐标系 |
| `clips` | 动作片段索引（起止时间、阶段），可选 |
| `records` | **核心**：按时间戳排列的融合样本 |
| `metadata` | 导出阶段、采样步长等 |

## 3. 核心记录 `MotionRecord`

每条记录 = **某一时刻、某一学生** 的融合结果。

```json
{
  "student_id": "8f3c2a1b-9e4d-4c1a-b2f0-123456789abc",
  "timestamp_ms": 5300.0,
  "action_type": "free_throw",
  "action_phase": "release",
  "clip_id": "8f3c2a1b-9e4d-4c1a-b2f0-123456789abc:0",
  "skeleton_3d": { ... },
  "ball": { ... },
  "identity_confidence": "high",
  "pose_source": "triangulated",
  "metadata": {}
}
```

### 3.1 学生 ID

- 类型：字符串 UUID（与 `enrollment` / `register_student` 一致）
- 跨机位、跨 clip 唯一标识学生，**不用** `track_id`

### 3.2 时间戳

- `timestamp_ms`：float，会话统一时间轴
- 来源：`frame_idx / fps * 1000`，可加 `camera_time_offsets_ms` 校正
- 融合时在各机位 pose2d 中取 **最近时间** 样本（`max_drift_ms` 窗口内）

### 3.3 动作类别与阶段

| 字段 | 取值示例 |
|------|----------|
| `action_type` | `pass` · `triple_threat` · `free_throw` · `jump_shot` · `layup` · `unknown` |
| `action_phase` | `load` · `set` · `release` · `follow_through` · `approach` · `gather` · `takeoff` · `finish` · `full` · `none` |

- 规范五类见 `src/action/registry.py`（`triple_threat` 含突破；遗留 `dribble`→三威胁，`jumper`→跳投）
- 无动作上下文时：`action_type: "unknown"`, `action_phase: "none"`
- `clip_id` 格式建议：`{student_id}:{clip_index}`

### 3.4 三维骨架 `skeleton_3d`

```json
{
  "format": "h36m_17",
  "joint_names": ["pelvis", "right_hip", "..."],
  "joints": [[x, y, z], ...],
  "joint_scores": [0.95, 0.92, ...]
}
```

| 项 | 约定 |
|----|------|
| 默认格式 | **H36M-17**（与评分、库里模板一致） |
| 坐标 | 与 `coordinate_system` 一致，单位米 |
| `joints` | 长度 17 的数组，顺序与 `joint_names` 或格式规范一致 |
| `joint_scores` | 可选，每关节置信度 |

后续可扩展 `format: "coco_133"`，通过 `format` 区分解析方式。

### 3.5 篮球点位 `ball`

```json
{
  "position": [0.36, 2.75, 1.82],
  "confidence": 0.78,
  "status": "tracked",
  "source_camera": "cam_04"
}
```

| `status` | 含义 |
|----------|------|
| `tracked` | 模型/检测器给出稳定 3D 位置 |
| `predicted` | 轨迹外推（短暂遮挡） |
| `not_visible` | 当前帧未检测到球 |
| `not_available` | 本帧无球模块输出（遮挡/未跑球轨） |

`position` 为 `null` 时仍保留 `status`，便于前端区分「没球」与「未跑检测」。进球模块见 `src/shot/outcome.py`（**已接入**）。

## 4. 坐标系 `coordinate_system`

```json
{
  "space": "court_world",
  "unit": "meter",
  "origin": "near_baseline_midpoint",
  "axes": "x_right, y_toward_center_line, z_up",
  "note": "与 configs/calibration/court_landmarks_fiba.yaml 一致"
}
```

| `space` | 场景 |
|---------|------|
| `court_world` | Pose2Sim 三角化后的球场坐标（**目标**） |
| `camera_normalized` | 单目归一化（过渡） |
| `pseudo3d` | demo 伪深度（仅可视化） |

---

## 5. 动作片段索引 `clips`（可选）

用于快速定位 phase 边界，不必遍历全部 `records`：

```json
{
  "clip_id": "8f3c2a1b-...:0",
  "student_id": "8f3c2a1b-...",
  "action_type": "free_throw",
  "start_ms": 4033.3,
  "end_ms": 6200.0,
  "release_ms": 5300.0,
  "anchor_camera": "cam_03",
  "zone_id": "zone_free_throw",
  "phases": [
    { "name": "load", "start_ms": 4033.3, "end_ms": 4700.0 }
  ]
}
```

## 6. 数据流：谁写入、谁读取

```
perception (×4)  →  pose2d + timestamp_ms + student_id
        ↓
sync + pose3d      →  triangulated skeleton @ timestamp_ms
        ↓
action segmenter   →  clips + action_type/phase 标注到时间轴
        ↓
shot (cam_04)      →  ball.position @ timestamp_ms
        ↓
export             →  SessionOutput (motion.json / .jsonl)
        ↓
scoring / UI / 3D viewer
```

| 生产者 | 填入字段 |
|--------|----------|
| ReID | `student_id`, `identity_confidence` |
| temporal | `timestamp_ms` |
| pose3d | `skeleton_3d`, `pose_source` |
| action | `action_type`, `action_phase`, `clips` |
| shot/outcome | `ball` |

---

## 7. JSONL 变体（大规模）

每行一个 `MotionRecord`，适合长 session：

```jsonl
{"student_id":"...","timestamp_ms":5300.0,"action_type":"free_throw",...}
{"student_id":"...","timestamp_ms":5333.3,"action_type":"free_throw",...}
```

文件头可另存 `manifest.json` 携带 `coordinate_system` 与 `clips`。

## 8. 与现有类型的关系

| 现有 | 新 schema |
|------|-----------|
| `DetectionRecord.student_id` | `MotionRecord.student_id` |
| `pose2d.frames[].timestamp_ms` | `MotionRecord.timestamp_ms` |
| `ActionClip` | `ActionClipRef` + 写入各 record 的 phase |
| `ShotOutcome` | 汇总进 `ball` + clip 级 `made`（未来扩展） |
| `curry_free_throw.json` | 参考模板，非 session 输出 |

Pydantic 定义：`src/output/schema.py`  
类名：`MotionRecord`, `SessionOutput`
